例如从未分析的原生库导出伪代码：

```bash
export JAVA_HOME=/workspace/apk-analysis/tools/jdk-21.0.8+9
export XDG_CONFIG_HOME=/workspace/apk-analysis/tools/config
mkdir -p /workspace/apk-analysis/tools/new-ghidra-projects
/workspace/apk-analysis/tools/ghidra_11.4.2_PUBLIC/support/analyzeHeadless \
 /workspace/apk-analysis/tools/new-ghidra-projects example \
 -import /workspace/yichantong/restored/android/lib/arm64-v8a/libexcavator.so \
 -max-cpu 4 -analysisTimeoutPerFile 180 \
 -scriptPath /workspace/yichantong/restored/scripts/ghidra \
 -postScript ExportAlgorithms.java /workspace/apk-analysis/new-native-export
```

`ExportAlgorithms` 可选第二个参数为函数名的正则表达式。默认跳过外部/跳板函数；被跳过的导出跳板通常指向已导出的内部实现，必须结合原 ELF 定位。不要将 index.tsv 的行数当作所有导出 API 的已验证实现数。

原始未推定类型的 Ghidra 输出用于保留证据；人工内联/类型调整后的版本用于辅助阅读。脚本的退出码与日志、各函数的成功/失败状态需要同时检查。

工程构建与分析均使用现有工作目录，不创建 Git worktree。原始 APK、LFS 指针和恢复 DEX 的哈希见前一轮解析报告。
